# 归属按来源决定，历史哈希冻结

清单里每个文件的归属不再由一张按路径匹配的规则表决定，而是看文件从哪来：依赖装进来的都是托管；custom_config 里的默认是配置，例外在 `package_cfg.json` 的 `base_config_roles` 和各依赖的 `config_roles` 里声明。原来的规则表和托管目录各写在一处，两边没有交叉校验，托管目录里可能出现配置文件，客户端整体替换时就会把用户的修改删掉；契约测试拿来比对的又是同一份数据，所以永远通过，查不出这种错。现在归属和托管目录都由依赖布局给出，加载打包配置时就校验它们一致。

## Consequences

- 已经移除的路径没有来源可查，判断它是不是过时文件只能靠记录下来的归属：上一版清单里的 role，或者 `manifest-history.json` 里的 role，两者不一致时以上一版清单为准。`manifest-history.json` 用旧规则一次性补上了归属，此后冻结。早于清单的安装包不会再有，所以删掉了从老 zip 重新生成历史哈希的脚本；如果恢复路径规则表，就得把这个生成脚本连同规则一起找回来。
- 来源不明的文件不再导致构建失败，而是按托管处理，因为它只可能是某个依赖装进来的。
